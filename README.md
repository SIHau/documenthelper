# 公文小幫手

協助撰寫公文的工具。用表單填寫內容，程式自動編號、排版、檢查格式與用語，最後一鍵輸出 PDF、ODT 或 DOCX。

- **不使用 AI**：格式與用語檢查全部是固定規則，結果可預期、可調整。
- **資料留在自己電腦**：稿件、範本、通訊錄只存在本機，不會上傳到任何伺服器。
- **兩種使用方式**：用瀏覽器開啟（網頁版），或安裝成桌面程式（Windows、macOS、Linux）。

> 檢查規則、用語庫與內建範本是依常見公文慣例整理的，尚未逐條對照《文書處理手冊》。正式使用前，請依貴機關的習慣確認。

## 功能一覽

| 功能 | 說明 |
|---|---|
| 文種 | 函、書函、公告、開會通知單、簽 |
| 結構化填寫 | 分欄填寫，主旨、說明、辦法（或依據、公告事項、擬辦）自動分項編號 |
| 即時預覽 | 所見即所得，預覽與匯出使用同一份版面 |
| 檢查 | 必填欄位、主旨期望語、行文方向與用語是否相符、附件是否一致、西元年份、口語詞等 |
| 用語庫 | 主旨句型、引敘、過渡、結尾、依行文方向分類的期望語，點一下即插入 |
| 匯出 | PDF、ODT、DOCX |
| 歷史稿件 | 儲存、開啟、複製、搜尋 |
| 範本 | 內建 6 個範本，也可把自己的稿件存成範本 |
| 通訊錄 | 機關資料管理，填寫時自動帶入；支援 CSV 匯入匯出 |
| 備份與還原 | 一次匯出或還原所有資料 |

## 開始使用

### 方式一：桌面程式（推薦）

1. 開啟專案的 **[Releases 頁面](https://github.com/SIHau/documenthelper/releases/latest)**，在最新版本底下的 **Assets** 下載對應系統的安裝檔：

   | 系統 | 下載檔案 |
   |---|---|
   | Windows | `…_x64-setup.exe` |
   | macOS（Intel 與 Apple 晶片皆可） | `…_universal.dmg` |
   | Linux | `….deb`、`….rpm` 或 `….AppImage` |

   > 檔名開頭的中文產品名稱會被 GitHub 省略，所以看起來像 `_0.1.0_x64-setup.exe`，檔案本身沒有問題。

2. 安裝並開啟。

安裝檔目前**未經簽章**，第一次開啟會有系統警告：

- **Windows**：出現 SmartScreen 時，點「其他資訊」→「仍要執行」。
- **macOS**：到「系統設定 → 隱私權與安全性」，允許開啟該程式。

### 方式二：網頁版

需要先安裝 [Node.js](https://nodejs.org) 18 以上：

```bash
npm install
npm run dev
```

然後用瀏覽器開啟終端機顯示的網址（通常是 `http://localhost:1420`）。

## 使用說明

畫面左邊是填寫表單，右邊有六個頁籤：**預覽、檢查、用語庫、稿件、範本、通訊錄**。

### 1. 撰寫一份公文

1. 在「文種」選擇公文種類，表單會依文種顯示對應欄位。
2. 選擇「行文方向」（上行、平行、下行），檢查功能會據此判斷期望語是否恰當。
3. 填寫發文機關、受文者、發文日期、發文字號等基本資料。
4. 填寫主旨。主旨只能一段，不能換行。
5. 填寫說明、辦法等分項內容（見下）。
6. 有需要時填寫附件、正本、副本，以及文末簽名（頭銜、姓名）。
7. 切到「預覽」確認版面，再匯出。

**分項與編號**：每一項右邊有按鈕，可以降一層（→）、升一層（←）、上移（↑）、下移（↓）、在下方新增（＋）、刪除（✕）。編號會自動依層級產生：

```
一、    第一層
(一)    第二層
1、     第三層
(1)     第四層
甲、    第五層
(甲)    第六層
```

層級不能跳級，調整順序後編號會自動重排。

**各文種的差異**

| 文種 | 主要欄位 |
|---|---|
| 函、書函 | 主旨、說明、辦法、正本、副本 |
| 公告 | 主旨、依據、公告事項（沒有受文者） |
| 開會通知單 | 開會事由、時間、地點、主持人、聯絡人及電話、出席者、列席者、備註（沒有主旨與說明） |
| 簽 | 主旨、說明、擬辦，文末有「敬陳」對象 |

### 2. 簽名

在表單最下方的「簽名」可填頭銜與姓名，並選擇字體（預設為 Yuji Boku）。不需要時取消勾選「於文件下方顯示簽名」。

### 3. 檢查

切到「檢查」頁籤，會列出目前發現的問題，分為三級：

- **錯誤**：必填欄位沒填、日期格式不正確等。
- **注意**：主旨缺少期望語、行文方向與用語不符、內文提到附件但附件欄空白、尚有未填的「○」等。
- **建議**：主旨過長、缺少句號、使用口語詞、分項結尾缺標點等。

頁籤上的紅色數字是「錯誤」與「注意」的合計數量。

### 4. 用語庫

1. 先在左邊點一下想插入用語的文字欄位（例如主旨或某一分項）。
2. 切到「用語庫」，點想用的用語，就會插入游標所在的位置。

期望語會依目前的行文方向顯示對應的用語。電話、信箱、日期這類欄位無法插入。

### 5. 匯出

右上角有三個匯出按鈕：

- **下載 PDF**：直接產生 PDF，文字可選取、搜尋。本文為思源宋體，簽名為 Yuji Boku，字體已嵌入檔案，任何電腦開啟都一樣。
- **匯出 ODT**、**匯出 DOCX**：可用 Word、LibreOffice 等軟體再編輯。字體以名稱引用，開啟的電腦需安裝對應字體（簽名用 Yuji Boku），否則會改用預設字體。
- **列印**（僅網頁版）：使用瀏覽器的列印功能。

**檔名**：有填發文字號時，檔名就是發文字號（例如 `裙萌議侯字第20261140416001號.pdf`）；沒填時用「文種_日期_主旨前 15 字」。

桌面版匯出時會跳出「另存新檔」對話框，可自選位置；網頁版則由瀏覽器直接下載。

### 6. 歷史稿件

切到「稿件」頁籤：

- **儲存至歷史**：把目前的稿件存起來。已存過的稿件，按鈕會變成「儲存變更」。
- **開啟**：載入某份稿件繼續編輯。
- **複製**：以某份稿件為底建立新稿，日期改為今天、發文字號清空。
- **刪除**、**搜尋**（主旨、受文者、字號、內文皆可搜，多個關鍵字以空白隔開）、依文種篩選。

目前稿件會自動暫存，重新開啟程式仍在；但要留存並方便日後查找，請按「儲存至歷史」。開啟其他稿件或套用範本時，如果目前稿件有未儲存的變更，程式會先詢問。

### 7. 範本

切到「範本」頁籤：

- **我的範本**：輸入名稱後按「將目前稿件存為範本」。範本會保留機關、受文者、內文與簽名。套用時日期改為今天、發文字號清空。
- **內建範本**：檢送資料、函復、請求協助、開會通知單、公告、簽請核示。內容以「○」標示待填處，檢查頁籤會提醒尚未填寫。

### 8. 通訊錄

切到「通訊錄」頁籤，可新增、編輯、刪除、搜尋機關資料（名稱、機關代碼、地址、電話、傳真、電子信箱、備註）。

- 填「發文機關」時，輸入的名稱與通訊錄相符，會自動帶入機關代碼、地址與聯絡資料（只補空白欄位）。「受文者」則帶入機關代碼。
- 「正本」「副本」旁的「＋通訊錄」選單可直接加入機關名稱。
- **匯入 CSV**：第一列為標題列，欄位為「名稱、代碼、地址、電話、傳真、電子信箱、備註」，只有「名稱」必填。名稱相同的會更新，其餘新增。
- **匯出 CSV**：可用 Excel 開啟。

機關代碼請自行填入，本工具沒有內建官方代碼表。

### 9. 備份與還原

**資料只存在這台電腦的這個程式（或瀏覽器）中**，清除瀏覽資料、重灌系統或換電腦都會消失。請定期備份：

- 到「稿件」頁籤最下方展開「備份與還原」，按「匯出全部資料」，會存成一個 JSON 檔，包含稿件、範本與通訊錄。
- 需要還原時按「從備份檔還原」。相同項目會被覆蓋，其餘資料保留，不會刪除現有資料。

桌面版與網頁版的資料是各自獨立的；要在兩者之間搬移，請用備份與還原。

## 常見問題

**為什麼 PDF 的字體不是標楷體？**
標楷體是微軟授權的字體，無法內建於程式。PDF 使用開放授權的思源宋體，外觀相近。

**匯出的 ODT／DOCX 在別台電腦字體不一樣？**
這兩種格式只記錄字體名稱。需要每個人看到相同的樣子，請發送 PDF。

**PDF 提示「字體不含以下字元」？**
內容有內建字體沒有的字元（例如表情符號），該字元不會出現在 PDF 中，請改用其他寫法。

**支援電子公文交換嗎？**
目前還沒有。電子交換格式需要依官方規格實作，取得規格後才會加入。

## 開發者資訊

技術：React、TypeScript、Vite；桌面版使用 Tauri 2；資料存於 IndexedDB。

```bash
npm install
npm run dev            # 網頁版開發伺服器
npm test               # 單元測試
npm run build          # 型別檢查並建置網頁版

npm run desktop:dev    # 桌面版開發模式
npm run desktop:build  # 產生桌面版安裝檔（位於 src-tauri/target/release/bundle/）
```

桌面版本機開發需安裝 [Rust](https://rustup.rs) 與 [Tauri 系統相依套件](https://tauri.app/start/prerequisites/)。也可以只用 GitHub Actions 打包（`.github/workflows/desktop.yml`）：手動執行或推送 `v*` 標籤即可，推送標籤時會另外建立 Release 草稿。

主要目錄：

| 路徑 | 內容 |
|---|---|
| `src/model/` | 公文資料模型、文種設定、自動編號、民國日期 |
| `src/rules/` | 檢查規則與口語詞表 |
| `src/data/` | 用語庫與內建範本 |
| `src/export/` | 版面資料、ODT、DOCX、PDF 產生 |
| `src/db/` | IndexedDB、通訊錄 CSV、備份還原 |
| `src/components/` | 介面元件 |
| `src-tauri/` | 桌面版（Tauri） |

檢查規則與用語可直接調整：`src/rules/index.ts`、`src/rules/colloquial.ts`、`src/data/phrases.ts`；文種欄位設定在 `src/model/docTypes.ts`。

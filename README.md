# 公文小幫手

協助撰寫公文的工具。用表單填寫內容，程式自動編號、排版、檢查格式與用語，最後一鍵輸出 PDF、ODT 或 DOCX。

- **不使用 AI**：格式與用語檢查全部是固定規則，結果可預期、可調整。
- **資料留在自己電腦**：稿件、範本、通訊錄只存在本機，不會上傳到任何伺服器。
- **兩種使用方式**：用瀏覽器開啟（網頁版），或安裝成桌面程式（Windows、macOS、Linux）。

> 檢查規則與 AI skill 的撰寫指引，依「公文編輯筆記」教學資料整理（轉成 Markdown 放在 `.claude/skills/documenthelper/references/source/`，含《文書處理手冊》《公文書寫作實務》等）。規則仍是固定比對，正式使用前請依貴機關的習慣確認。

## 功能一覽

| 功能 | 說明 |
|---|---|
| 文種 | 函、書函、令、公告、開會通知單、催辦案件通知單、簽、議案關係文書，以及學生議會的審查報告對照表、糾正案、會議紀錄、簽到表、概算書 |
| 結構化填寫 | 分欄填寫，主旨、說明、辦法（或依據、擬辦）自動分項編號 |
| 即時預覽 | 所見即所得，預覽與匯出使用同一份版面 |
| 檢查 | 必填欄位、主旨期望語與字數、行文方向與稱謂是否相符、附件是否一致、限期是否寫進主旨、數字日期時間寫法、用字用語（公布／部分等）、口語詞、草案標題等 |
| 用語庫 | 主旨句型、引敘、過渡、結尾、依行文方向分類的期望語，點一下即插入 |
| 匯出 | PDF、ODT、DOCX |
| 限期與辦理期限 | 選填「限期辦理」日期，依速別算出辦理期限（最速件 1 天、速件 3 天、普通件 6 天），可一鍵把限期寫進主旨（速別留空） |
| 歷史稿件 | 儲存、開啟、複製、搜尋；單一稿件可匯出成 .json 檔交給別人接手 |
| 範本 | 內建 21 個範本（含學生議會各式文書），也可把自己的稿件存成範本 |
| 法規文字匯入 | 在草案對照表貼上或讀取法規 .txt，自動依章、條切開並挑選要放進表格的條文 |
| 通訊錄 | 機關資料管理，填寫時自動帶入；支援 CSV 匯入匯出 |
| 備份與還原 | 一次匯出或還原所有資料 |

## 開始使用

### 方式一：桌面程式（推薦）

1. 開啟專案的 **[Releases 頁面](https://github.com/SIHau/documenthelper/releases/latest)**，在最新版本底下的 **Assets** 下載對應系統的安裝檔：

   | 系統 | 下載檔案 |
   |---|---|
   | Windows | `…_x64-setup.exe` |
   | macOS（Intel 與 Apple 晶片皆可） | `…_universal.dmg` |
   | Linux | `….deb`、`….rpm` 或 `….AppImage` |

   > 檔名開頭的中文產品名稱會被 GitHub 省略，所以看起來像 `_0.1.0_x64-setup.exe`，檔案本身沒有問題。

2. 安裝並開啟。

安裝檔目前**未經簽章**，第一次開啟會有系統警告：

- **Windows**：出現 SmartScreen 時，點「其他資訊」→「仍要執行」。
- **macOS**：到「系統設定 → 隱私權與安全性」，允許開啟該程式。

### 方式二：網頁版

需要先安裝 [Node.js](https://nodejs.org) 18 以上：

```bash
npm install
npm run dev
```

然後用瀏覽器開啟終端機顯示的網址（通常是 `http://localhost:1420`）。

## 使用說明

畫面左邊是填寫表單，右邊有六個頁籤：**預覽、檢查、用語庫、稿件、範本、通訊錄**。

### 1. 撰寫一份公文

1. 在「文種」選擇公文種類，表單會依文種顯示對應欄位。
2. 選擇「行文方向」（上行、平行、下行、斜行），檢查功能會據此判斷期望語是否恰當。
3. 填寫發文機關、受文者、發文日期、發文字號等基本資料。
4. 填寫主旨。主旨只能一段，不能換行。
5. 填寫說明、辦法等分項內容（見下）。
6. 有需要時填寫附件、正本、副本，以及文末簽名（頭銜、姓名）。
7. 切到「預覽」確認版面，再匯出。

**限期與辦理期限**：函、書函可在「速別」旁填「限期辦理」（請受文者於某日前辦理）。表單會顯示辦理期限：自收文起算，最速件 1 個工作天、速件 3 個、普通件 6 個，限期較早時以限期為準；這裡以「發文當天收文」試算。只排除週六日，不含國定假日。按「把限期寫進主旨」會在主旨加入「於115年11月20日前辦理」（依手冊，期限寫在主旨、速別留空）；已設定限期但主旨沒寫到時，「檢查」頁籤會提醒。

**法規文字匯入對照表**：在議案關係文書與審查報告對照表的草案對照表上方按「匯入法規文字…」，貼上從 Word 複製的法規文字（或讀取 .txt 檔），按「解析條文」，勾選要放進表格的條文後「加入對照表」。修正案會在「現行條文」填入原條文，並把同一份複製到「修正條文」讓您直接修改；新訂填入「條文」；審查報告填入「現行條文」。折行的句子會自動接回，「第五條規定…」這類引用不會被誤判成新條文。

**分項與編號**：每一項右邊有按鈕，可以降一層（→）、升一層（←）、上移（↑）、下移（↓）、在下方新增（＋）、刪除（✕）。編號會自動依層級產生：

```
一、    第一層
(一)    第二層
1、     第三層
(1)     第四層
甲、    第五層
(甲)    第六層
```

層級不能跳級，調整順序後編號會自動重排。

**各文種的差異**

| 文種 | 主要欄位 |
|---|---|
| 函、書函 | 主旨、說明、辦法、正本、副本 |
| 令 | 發文日期與字號在受文者之前；受文者、主旨可留空，只寫本文（例：任命書） |
| 公告 | 主旨、依據、說明（沒有受文者、檔號與裝訂線） |
| 開會通知單 | 開會事由、時間、地點、主持人、聯絡人及電話、出席者、列席者、備註（每行一點）；填了議程標題、報告事項或討論事項時，第二頁印議程 |
| 催辦案件通知單 | 主旨、正本、副本 |
| 簽 | 主旨、說明、擬辦，文末有「敬陳」對象 |
| 議案關係文書 | 依學生議會樣張：頁首「學生議會第○屆」、案由、說明、提案人與連署人；草案對照表另起一頁（修正：修正條文｜現行條文｜說明；新訂：條文｜說明） |
| 審查報告對照表 | 標題為法規與草案名稱加「審查報告對照表」；表格依序為審查會通過條文、各併案提案（一案一欄）、現行條文、說明 |
| 糾正案 | 壹、被糾正機關，貳、案由，參、事實與理由，文末提案議員 |
| 會議紀錄 | 機關與會議名稱、時間地點主席、出席請假缺席列席、記錄人員；壹至伍各段，討論事項逐案填寫提案人、案由、說明與決議 |
| 簽到表 | 會議名稱與日期；應到人員姓名印在簽名格上方（每列七人），另有列席與旁聽人員欄 |
| 概算書 | 封面、目次、甲、總說明（壹、前言）與貳、概算案各自另起一頁；概算表依處室列出項目、編號、費用與說明，自動計算合計 |

### 2. 簽名

在表單最下方的「簽名」可填頭銜與姓名，並選擇字體（預設為 Yuji Boku）。不需要時取消勾選「於文件下方顯示簽名」。

### 3. 檢查

切到「檢查」頁籤，會列出目前發現的問題，分為三級：

- **錯誤**：必填欄位沒填、日期格式不正確等。
- **注意**：主旨缺少期望語、行文方向與用語不符、內文提到附件但附件欄空白、尚有未填的「○」等。
- **建議**：主旨過長、缺少句號、使用口語詞、分項結尾缺標點等。

頁籤上的紅色數字是「錯誤」與「注意」的合計數量。

### 4. 用語庫

1. 先在左邊點一下想插入用語的文字欄位（例如主旨或某一分項）。
2. 切到「用語庫」，點想用的用語，就會插入游標所在的位置。

期望語會依目前的行文方向顯示對應的用語。電話、信箱、日期這類欄位無法插入。

### 5. 匯出

函頭類文件（議案關係文書以外）依學生議會樣張排版：右上角檔號與保存年限、標題 20pt、發文日期等列 12pt、左右邊界 2.5 cm、每頁頁尾「第 X 頁 共 Y 頁」；函、令、開會通知單、催辦案件通知單在 PDF 與預覽的第一頁左側印裝訂線（ODT、DOCX 不含裝訂線）。

**發文字號**：選擇字別（議字、議令字、議佈字、議秘字、議通字、議件字）或按「產生」，會依發文日期產生「議字第1151014001號」格式的字號，最後三碼是當日流水號，依「稿件」中同字別、同日期已用的字號往下排。

右上角有三個匯出按鈕：

- **下載 PDF**：直接產生 PDF，文字可選取、搜尋。本文為思源宋體，簽名為 Yuji Boku，字體已嵌入檔案，任何電腦開啟都一樣。
- **匯出 ODT**、**匯出 DOCX**：可用 Word、LibreOffice 等軟體再編輯。字體以名稱引用，開啟的電腦需安裝對應字體（簽名用 Yuji Boku），否則會改用預設字體。
- **列印**（僅網頁版）：使用瀏覽器的列印功能。

**檔名**：有填發文字號時，檔名就是發文字號（例如 `裙萌議侯字第20261140416001號.pdf`）；沒填時用「文種_日期_主旨前 15 字」。

桌面版匯出時會跳出「另存新檔」對話框，可自選位置；網頁版則由瀏覽器直接下載。

### 6. 歷史稿件

切到「稿件」頁籤：

- **儲存至歷史**：把目前的稿件存起來。已存過的稿件，按鈕會變成「儲存變更」。
- **開啟**：載入某份稿件繼續編輯。
- **複製**：以某份稿件為底建立新稿，日期改為今天、發文字號清空。
- **刪除**、**搜尋**（主旨、受文者、字號、內文皆可搜，多個關鍵字以空白隔開）、依文種篩選。
- **匯出稿件檔**：把目前稿件存成 `.json` 檔（檔名為發文字號），可 Email 或用隨身碟交給別人；對方按「**開啟稿件檔**」就能接手編輯或回覆。格式與 StudentGov 的「公文原稿.json」相同。開啟時如果目前稿件有未儲存的變更，會先詢問；檔案不是稿件（或是整批備份檔）時會說明原因，不會動到目前的稿件。

目前稿件會自動暫存，重新開啟程式仍在；但要留存並方便日後查找，請按「儲存至歷史」。開啟其他稿件或套用範本時，如果目前稿件有未儲存的變更，程式會先詢問。

### 7. 範本

切到「範本」頁籤：

- **我的範本**：輸入名稱後按「將目前稿件存為範本」。範本會保留機關、受文者、內文與簽名。套用時日期改為今天、發文字號清空。
- **內建範本**：檢送資料、函復、請求協助、開會通知單、公告、簽請核示、議案關係文書（議員提案、黨團提案），以及學生議會的議會函文、議長令（兩式）、秘書長任命書、秘書長函文、議會公告、開會通知單（含議程）、催辦案件通知單、審查報告對照表、糾正案、會議紀錄、會議簽到表、概算書。內容以「○」標示待填處，檢查頁籤會提醒尚未填寫。

### 8. 通訊錄

切到「通訊錄」頁籤，可新增、編輯、刪除、搜尋機關資料（名稱、機關代碼、地址、電話、傳真、電子信箱、備註）。

- 填「發文機關」時，輸入的名稱與通訊錄相符，會自動帶入機關代碼、地址與聯絡資料（只補空白欄位）。「受文者」則帶入機關代碼。
- 「正本」「副本」旁的「＋通訊錄」選單可直接加入機關名稱。
- **匯入 CSV**：第一列為標題列，欄位為「名稱、代碼、地址、電話、傳真、電子信箱、備註」，只有「名稱」必填。名稱相同的會更新，其餘新增。
- **匯出 CSV**：可用 Excel 開啟。

機關代碼請自行填入，本工具沒有內建官方代碼表。

### 9. 備份與還原

**資料只存在這台電腦的這個程式（或瀏覽器）中**，清除瀏覽資料、重灌系統或換電腦都會消失。請定期備份：

- 到「稿件」頁籤最下方展開「備份與還原」，按「匯出全部資料」，會存成一個 JSON 檔，包含稿件、範本與通訊錄。
- 需要還原時按「從備份檔還原」。相同項目會被覆蓋，其餘資料保留，不會刪除現有資料。

桌面版與網頁版的資料是各自獨立的；要在兩者之間搬移，請用備份與還原。

## 讓 AI 使用公文小幫手（Skill 與命令列）

專案附有 Claude 的 skill：`.claude/skills/documenthelper/`。在這個專案裡使用 Claude Code 時會自動載入，AI 就能代您起稿、檢查、預覽與匯出公文，不必開網頁：

> 「幫我寫一份函給○○局，請他們提供活動場地使用時間，限期 11 月 20 日，輸出成 PDF。」

AI 會依 skill 的流程：釐清缺少的資訊 → 用範本或 `dh new` 起稿 → 填寫稿件 JSON → `dh check` 檢查並修正 → `dh preview` 給您確認 → `dh render` 匯出，同時留下稿件檔，您可以在「稿件 → 開啟稿件檔」匯入繼續編輯。

背後是同一份程式的命令列（`cli/dh.ts`），結果與網頁、桌面版完全一致，也可以自己用：

```bash
npm ci
bash .claude/skills/documenthelper/scripts/dh.sh help             # 所有指令
bash .claude/skills/documenthelper/scripts/dh.sh new 函 --sender "○○機關" --recipient "○○單位" > draft.json
bash .claude/skills/documenthelper/scripts/dh.sh check draft.json
bash .claude/skills/documenthelper/scripts/dh.sh render draft.json --format pdf --out out
```

（也可以用 `npm run dh -- <指令>`。）若把 skill 複製到別的專案或 `~/.claude/skills/`，請設定環境變數 `DOCUMENTHELPER_DIR` 指向本專案根目錄。skill 要求 AI 不得編造機關、人名、字號與日期，缺資料時先詢問或以「○」標示並提醒補齊。

## 常見問題

**為什麼 PDF 的字體不是標楷體？**
標楷體是微軟授權的字體，無法內建於程式。PDF 使用開放授權的思源宋體，外觀相近。

**匯出的 ODT／DOCX 在別台電腦字體不一樣？**
這兩種格式只記錄字體名稱。需要每個人看到相同的樣子，請發送 PDF。

**PDF 提示「字體不含以下字元」？**
內容有內建字體沒有的字元（例如表情符號），該字元不會出現在 PDF 中，請改用其他寫法。

**支援電子公文交換嗎？**
目前還沒有。電子交換格式需要依官方規格實作，取得規格後才會加入。

## 開發者資訊

技術：React、TypeScript、Vite；桌面版使用 Tauri 2；資料存於 IndexedDB。

```bash
npm install
npm run dev            # 網頁版開發伺服器
npm test               # 單元測試
npm run build          # 型別檢查並建置網頁版

npm run desktop:dev    # 桌面版開發模式
npm run desktop:build  # 產生桌面版安裝檔（位於 src-tauri/target/release/bundle/）
```

桌面版本機開發需安裝 [Rust](https://rustup.rs) 與 [Tauri 系統相依套件](https://tauri.app/start/prerequisites/)。也可以只用 GitHub Actions 打包（`.github/workflows/desktop.yml`）：手動執行或推送 `v*` 標籤即可，推送標籤時會另外建立 Release 草稿。

主要目錄：

| 路徑 | 內容 |
|---|---|
| `src/model/` | 公文資料模型、文種設定、自動編號、民國日期 |
| `src/rules/` | 檢查規則與口語詞表 |
| `src/data/` | 用語庫與內建範本 |
| `src/export/` | 版面資料、ODT、DOCX、PDF 產生 |
| `src/db/` | IndexedDB、通訊錄 CSV、備份還原 |
| `src/components/` | 介面元件 |
| `src-tauri/` | 桌面版（Tauri） |
| `cli/` | 命令列 `dh`（起稿、檢查、預覽、匯出），給 AI skill 與腳本使用 |
| `.claude/skills/documenthelper/` | 讓 AI 使用公文小幫手的 skill：流程、欄位說明、撰寫指引與範例稿件 |

檢查規則與用語可直接調整：`src/rules/index.ts`、`src/rules/colloquial.ts`、`src/data/phrases.ts`；文種欄位設定在 `src/model/docTypes.ts`。
